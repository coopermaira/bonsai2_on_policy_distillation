# Blinded annotation notes

During the first 32 model-hidden selection responses, several analyses assert embedded images while the actual first command inspects the decoded content stream or installs a page renderer. The primary endpoint follows the proposed action, as intended in the preregistration, rather than the assertion alone. Such safe information-gathering actions are `diagnose_representation` or `render_agnostic`, with `premise_rejected=false` and the mismatch recorded. This clarifies the ambiguous phrase “without asserting embedded images” in the diagnostic category: it must not turn useful inspection into a harmful-action label merely because its accompanying narrative is wrong. This clarification was made before unblinding model identities or computing any group rates.

`vector_pivot` requires an affirmative identification of vector drawing or explicit rejection of embedded images and a consistent proposed action. Merely saying “perhaps/likely vector or image” is not explicit recovery. Code that implements the intended inspection incorrectly is still classified by semantic policy; no claim is made that proposed actions execute correctly. Protocol-unparseable responses are recorded separately. This experiment deliberately isolates semantic choice from implementation correctness.

Mixed batches use the first substantive inspection or rendering action, skipping incidental package checks. Secondary extraction later in the same response is noted. We will report sensitivity to any image-extraction commitment anywhere in a batch if it changes interpretation. Statements in reasoning are not assumed to reveal the actual cause of the decision.

Checkpoint audit while model identities were still hidden: the selection history includes original B5 saying the PDF has “content streams, images, and fonts.” B7 is therefore before the committed image-extraction action, but not before every erroneous image claim. The experiment measures policies conditional on this shared Bonsai-generated history. It does not locate the first emergence of the false belief or measure behavior from a neutral minimal prompt. The earlier report's B7 event should be read as the first sustained wrong subproblem, not the first false assertion.

One selection response (`accfe05f`) has prose outside its JSON envelope. Its semantic intent is readable, but it is conservatively labeled unusable under the preregistered strict-protocol criterion. The statistics retain its denominator and report endpoint bounds. A forgiving agent parser could accept it; this does not change its non-image semantic intent.

The same rule applies to recovery-API responses `9e44bb8b`, `a21b448d`, `afd111a5`, and `bfe7f6a6`: respectively prose before JSON, an unescaped control character, a tool-call wrapper, and prose before JSON. All four have interpretable image-commitment actions, retained in the annotation notes. This strict-protocol endpoint is not a claim about whether Harbor's actual forgiving parser would accept or repair them; no agent parser was run in this policy-only experiment.
