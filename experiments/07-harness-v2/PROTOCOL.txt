PAIRED BONSAI/QWEN STUDY, OCTOBER 4–5 2026

Authorized cutoff: Monday October 5, 09:00 America/Chicago (14:00 UTC).
Slurm controls all compute. Three Qwen servers each occupy a different GPU;
two Bonsai servers share the fourth. No training. Eight new tasks, one attempt
per model per task. Tasks were selected for varied, locally executable work;
this is a small purposive sample, not an unbiased overall capability estimate.

Common attempt budget: 262,144 generated tokens including reasoning, 512
model decisions, 16,384 generated tokens per response, 65,536 context tokens.
Same per-task seed and sampling parameters for both models. No latency,
throughput, or task deadline is a scoring criterion. The authorized allocation
cutoff pauses unfinished attempts; it is not a zero score. Verifier operational
timeouts produce unknown results and score bounds, not incorrect answers.
No official Terminal-Bench leaderboard score is claimed.

This custom common harness replaces the earlier Terminus execution layer.
It uses a native act function, noninteractive bash, and explicit wait/recall actions.
Consequently comparisons with the earlier five tasks are descriptive, not a
controlled attribution of differences to the model alone.

Context management uses the actual server tokenizer and chat template. It
reserves the full response allowance before each request. When needed it keeps
the immutable task, model-maintained notebook, and recent observations, while
older turns remain retrievable from the complete archive. This is deterministic
context compaction, not an LLM-written summary. The notebook can be wrong or
incomplete; it is labeled as model-authored. Raw reasoning and tool outputs are
archived. Large shell output remains available in the task filesystem.

Every completed decision commits a filesystem image and durable state.
Exported shell environment and working directory survive new shell commands.
Allocation recovery preserves files, not live processes: the model receives a
notice to inspect state and restart services. Interrupted commands are never
automatically replayed. Lost model responses reserve their full possible usage
and flag the attempt as censored rather than inventing exact token accounting.
Interrupted attempts require explicit supervised resumption within authorized
resources; the controller does not blindly restart failed requests.

Partial functional credit is the equally weighted mean of prespecified
requirement-group pass fractions. Parameterized cases share their requirement
group's weight. Report baseline, final, improvement bounds, and regressions;
these are functional percentages, not calibrated success probabilities.
Unknown checks are not silently treated as failures or dropped. Fixture/oracle
self-tests are excluded. Missing implementations cannot receive error-exit or
empty-output credit. Reference solutions are checked in separate containers.
WAL's performance gate is excluded. HTML browser-observation failures are
unknown, correcting the supplied evaluator's timeout-as-pass behavior.

Reference solutions, hidden tests, rubrics, Docker socket, and model servers
are never mounted into agent task containers. Evaluation runs on exported
artifacts in independent containers. Agent containers have bounded CPUs/RAM,
no GPUs or host mounts, and ordinary network access for task dependencies.

Process evaluation is a separate independent frontier-model review, pending
until trajectories exist. Review the task and reference, cite turn IDs, and
score requirement understanding, evidence gathering, decision quality,
implementation/tool use, and verification/recovery each 0–4. Plausible prose
alone earns no implementation credit. Keep process scores distinct from
functional test scores; record judge uncertainty. The running Qwen and Bonsai
instances do not grade themselves. Review packets are generated after runs.

Files: runs/oct04-eight-new-tools/manifest.json, servers.json, status.json,
<model>-<task>/state.json, request-*.json, response-*.json, turns/*.json,
artifacts/, verification/, functional-results.json, and review/.

HTML evaluator correction: browser HTTP(S) requests are intercepted so external
network stalls cannot determine scores. An attempted external script load is
counted as retained executable content (failure), then aborted. Other external
resources are aborted, allowing local event handlers and sentinels to run.
These are explicitly modified, offline functional checks, not the official test.

Startup pilots 5764, 5767, and 5768 were stopped and excluded. The initial
hand-written JSON protocol caused serialization errors. Merely recognizing
native wrappers did not resolve malformed JSON. The final common interface
uses the server's native function-calling API with one act function and keeps
assistant tool calls, reasoning, and matching tool-result messages in history.
Both models use the same function schema and semantic action validation.
Scored attempts restart from pristine task states in runs/oct04-eight-new-tools/.
Pilots remain in the other oct04-eight-new* directories for audit; do not pool
them with scored attempts. Server ports are job-specific, readiness verifies
the owned server process, and cancellation traps remove owned containers.
